# 메일 업무 도우미

친구의 Windows PC에서 **POP3 메일함**의 새 메일을 확인하고, **ChatGPT 계정으로 로그인한 Codex CLI**로 내용을 분석한 뒤 데스크톱 Excel에 반영합니다. 별도 OpenAI API 키를 사용하지 않습니다. 답변은 초안만 만들며 메일을 발송하거나 서버 메일을 삭제하지 않습니다.

메일 서버는 **설정에서 직접 입력**합니다. 기본값이 하이웍스(`pop3s.hiworks.com:995`)일 뿐, POP3(SSL)를 지원하는 메일 계정이면 어디든 서버 주소와 포트를 바꿔 그대로 쓸 수 있습니다. 특정 서비스에 맞춘 코드는 없습니다.

## 준비 사항

- Windows 10/11, 데스크톱 Microsoft Excel 설치 및 최초 실행/인증 완료
- Node.js LTS: https://nodejs.org/ (Codex CLI 설치에 사용)
- 친구 본인의 ChatGPT Plus 계정과 Codex 사용 가능 상태
- POP3(SSL)를 지원하는 메일 계정, 해당 서비스에서 **POP3 사용 설정**, 그리고 메일 전용(앱) 비밀번호를 발급하는 서비스라면 그 비밀번호
- PC 전원과 인터넷 연결. 절전·로그아웃 중에는 처리하지 않으며, 로그인 후 다시 수집합니다.

메일 본문은 Codex 분석을 위해 OpenAI로 전송됩니다. 메일 비밀번호는 Windows 자격 증명에 보관하며 Codex 프롬프트에 넣지 않습니다. Plus 사용량 한도를 소모하고, 한도나 인증 문제 발생 시 분석을 대기합니다. 이 프로그램은 사용량 한도를 우회하지 않습니다.

## 설치

1. PowerShell에서 다음 명령으로 Codex를 설치합니다.

   ```powershell
   npm install -g @openai/codex
   codex login
   codex login status
   ```

   브라우저에서 **친구 본인의 ChatGPT 계정**으로 로그인하세요. 마지막 명령 결과가 ChatGPT 로그인인지 확인합니다. 인증 파일을 친구와 주고받지 마세요.

2. [Releases](https://github.com/gakmax/mail-assistant/releases/latest)에서 `MailAssistant-Setup-x.y.z.exe`를 내려받아 실행합니다.

3. **“Windows가 PC를 보호했습니다” 경고가 나오면 `추가 정보` → `실행`을 누르세요.** 코드 서명 인증서를 쓰지 않아서 나오는 경고이며, 파일이 손상되었다는 뜻은 아닙니다. 같이 올라온 `.sha256` 파일과 `Get-FileHash MailAssistant-Setup-x.y.z.exe -Algorithm SHA256` 결과를 비교하면 무결성을 직접 확인할 수 있습니다.

4. 설치 마법사에서 바탕화면 바로가기와 자동 시작 여부를 고릅니다. **관리자 권한은 필요 없습니다** — UAC 창이 뜬다면 취소하고 다시 받으세요. 로그인한 사용자 계정에만 설치되며, 그래야 Codex CLI를 제대로 찾습니다.

5. 바탕화면의 **메일 도우미** 바로가기를 엽니다.
6. **설정**에서 메일 계정, 메일 전용 비밀번호, 엑셀 파일 위치를 입력하고 **시작**을 누릅니다.

기본 서버는 `pop3s.hiworks.com`, SSL 포트는 `995`, 조회 간격은 `180초`입니다. **다른 메일 서비스를 쓴다면 설정에서 서버 주소와 포트를 바꾸면 됩니다** — 아래 표는 흔한 예이고, 정확한 값은 각 서비스의 POP3 안내를 따르세요.

| 서비스 | POP3 서버 | 포트 |
|---|---|---|
| 하이웍스 (기본값) | `pop3s.hiworks.com` | 995 |
| Gmail | `pop.gmail.com` | 995 |
| 네이버 | `pop.naver.com` | 995 |
| 다음 | `pop.daum.net` | 995 |
| Outlook.com | `outlook.office365.com` | 995 |

어느 서비스든 **웹메일 설정에서 POP3를 먼저 켜야** 하고, 2단계 인증을 쓰는 계정은 일반 로그인 비밀번호가 아니라 **앱 비밀번호(메일 전용 비밀번호)** 를 발급해 입력해야 합니다. 회사 메일은 허용 국가/IP 정책에서 실행 PC의 접근이 가능해야 합니다. SSL 없는 평문 POP3(110)는 지원하지 않습니다. 값을 입력한 뒤 **연결 테스트**로 접속·인증·목록 조회까지 확인하고 시작하세요.

**첫 성공 연결 시점에 이미 존재하는 메일은 분석하지 않습니다.** 연결 완료를 확인한 뒤 새 테스트 메일을 보내세요. 프로그램 설정을 입력한 시각이 아닌, 첫 POP3 연결에 성공한 시각이 기준입니다. 서버/계정을 바꾸면 해당 계정의 기준점을 새로 설정합니다.

## 평소 사용

- 메일 도우미를 실행한 뒤 엑셀 파일은 평소처럼 더블클릭해서 엽니다.
- 도우미 창을 **최소화**하면 계속 처리합니다. 닫기(X)는 작업 종료 요청입니다. 트레이 상주 기능은 없습니다 — 계속 돌려 둘 생각이면 닫지 말고 최소화하세요.
- **업데이트는 창을 열 때 자동으로 확인합니다.** 새 버전이 있으면 대시보드 위에 안내 창이 뜹니다. 서버에 매번 묻지는 않고 마지막 확인에서 6시간이 지났을 때만 확인하므로, 지금 당장 보고 싶으면 **설정 → 업데이트 지금 확인**을 누르세요. 소스에서 직접 실행한 경우에는 바꿔 칠 설치본이 없으므로 확인하지 않습니다.
- 열린 대상 통합문서에 직접 반영합니다. 시트 선택을 강제로 옮기지 않습니다.
- 대상 파일이 닫혀 있으면 별도 Excel 인스턴스로 열어 저장 후 닫습니다.
- 파일이 다른 프로세스에 잠겼거나 셀 편집/대화상자 때문에 Excel이 응답하지 않으면 다음 주기에 재시도합니다.
- **열린 통합문서를 자동 저장하므로, 친구가 아직 저장하지 않은 편집도 함께 저장됩니다.**
- 메일 확인 간격 + Codex 분석 시간이 지난 후 화면에 반영됩니다. 즉시 수신 푸시는 아닙니다.
- 중지는 현재 POP3/Codex 작업을 마친 뒤 적용됩니다. Codex 한 건의 제한 시간은 4분입니다.

## 시트와 직접 수정할 부분

| 시트 | 내용 | 직접 관리할 열 |
|---|---|---|
| 메일 목록 | 발신자, 제목, 종류, 요약, 요청사항, 첨부 이름 | 처리 상태 |
| 일정 | 일정명, 시작, 마감, 원문 근거, 확인 필요 | 처리 상태 |
| 우선순위 | 우선순위와 판단 근거, 다음 행동 | 처리 상태 |
| 답변 초안 | 답변이 필요한 메일의 제목과 초안 | 사용자 수정본, 검토 상태 |
| 실행 상태 | 확인 시각, 반영 시각, 대기 건수, 안내 | 자동 관리 |
| 일정 달력 | 이번 달·다음 달 월간 그리드, 지난 마감 목록 | 자동 생성 (직접 수정 금지) |

생성된 행은 이후 덮어쓰지 않습니다. 메일 종류와 상태는 표의 필터로 골라 볼 수 있습니다. 시트 이름, 첫 행의 열 이름·순서, 메일 ID/항목 ID는 변경하지 마세요. 열 순서를 바꾸면 자동 반영을 중단합니다. 처리한 행을 삭제해도 자동으로 복원하지 않습니다.

## 창 구성

창은 상태 카드, 버튼 줄, 기록 영역으로 나뉩니다. 상태 카드는 실행 여부, Codex 로그인, 메일 비밀번호 저장 여부, 마지막 확인 시각을 색 점으로 보여줍니다. 계정·서버·엑셀 경로 같은 입력값은 **설정** 창으로 옮겼고, 실행 중에는 설정을 열 수 없습니다.

- `▶ 시작` / `■ 중지` — 중지는 현재 작업을 마친 뒤 적용됩니다
- `⟳ 지금 확인` — 다음 주기를 기다리지 않고 즉시 한 번 조회합니다
- `⇄ 연결 테스트` — 저장된 비밀번호로 POP3 접속·인증·목록 조회만 해봅니다. 설정 창에서는 입력 중인 값으로 시험합니다
- `⌨ Codex 로그인` — 로그인 창을 열고, `Codex 상태 다시 확인`으로 결과를 반영합니다
- `📁 데이터 폴더` — `mail.db`와 `status.json`이 있는 폴더를 엽니다

Codex 로그인 상태와 연결 테스트는 별도 스레드에서 실행되어 창이 멈추지 않습니다.

## 화면

**메일 도우미 창이 곧 이 화면들입니다.** 바로가기를 누르면 아래 열 개 페이지가 든 창이
열립니다. 겉은 데스크톱 창이고 속은 웹 화면이며, Discord·Slack·VS Code와 같은 방식입니다 —
다만 크롬을 동봉하지 않고 Windows에 이미 있는 **WebView2**(Edge 엔진)를 빌려 쓰므로 설치본이
4MB만 늘어납니다.

`127.0.0.1`에만 열리고 매번 포트가 달라지며, 토큰이 없는 주소로는 내용이 보이지 않습니다.
같은 PC 밖에서는 접속할 수 없습니다.

브라우저로 같은 화면을 열고 싶으면 시작 메뉴의 **메일 도우미 (진단)**에서:

```powershell
MailAssistantTools.exe web --browser
```

창이 열리지 않거나 화면이 깨지면 **예전 창으로 돌아갈 수 있습니다**:

```powershell
MailAssistant.exe --window
```

### 창의 짜임

왼쪽은 **어디로 갈까**, 위쪽은 **지금 어떤 상태인가**입니다.

- **왼쪽 사이드바**에 열 페이지가 업무·도움·시스템으로 묶여 있고, 손댈 것이 남은 곳에는
  숫자가 붙습니다 — **메일**에는 미처리 건수, **할 일**에는 판에 남은 카드 수, **초안**에는
  검토 전 초안 수. **메모에는 붙지 않습니다** — 메모는 전부 그냥 메모라 미처리라는
  것이 없고, 줄지 않는 숫자는 곧 읽지 않게 되기 때문입니다.
  대시보드의 카드와 같은 숫자이며(0이면 아무것도 그리지 않습니다),
  다른 화면에서 무엇을 하든 몇 초 안에 따라옵니다.
- 위쪽 띠 맨 왼쪽의 **≡ 단추**로 사이드바를 **접었다 폈다** 합니다. 접으면 아이콘만
  남고 숫자는 아이콘 어깨에 작게 붙으며, 아이콘에 마우스를 올리면 이름이 나옵니다.
  고른 상태는 그 PC의 브라우저에 남아, 화면을 옮기거나 창을 다시 열어도 그대로입니다.
- 창이 좁아지면(1200px 미만) 아무것도 고르지 않아도 사이드바가 **저절로 접힙니다.**
  좁은 창에서도 ≡ 단추로 다시 펼 수 있습니다.
- **위쪽 띠**에는 뒤로가기, 지금 보고 있는 화면 이름, **수집 중 / 수집 멈춤** 표시가
  있습니다. 새 버전이 있으면 그 옆에 **새 버전 0.0.0**이 떠서 누르면 실행 화면으로
  갑니다. 창에는 브라우저의 뒤로가기가 없으므로, 카드를 눌러 들어간 화면에서
  돌아오는 길은 이 화살표입니다.

| 페이지 | 내용 |
| --- | --- |
| 대시보드 | 맨 위에 **오늘의 AI 브리핑** — 분석이 끝난 메일의 요약과 집계만 모아 Codex에게 하루 한 번 물어 만든 한 문단과 몇 줄짜리 항목, 그리고 **먼저 볼 메일** 몇 건(누르면 그 메일이 열립니다). 하루 한 번, **오전 8시 이후 첫 수집 차례에** 만들어지고 그때까지는 그렇게 적혀 있습니다. **분석 대기가 남아 있으면 미룹니다** — Codex는 한 번에 하나만 돌고 아침에 온 메일의 분석이 먼저이기 때문입니다. **다시 만들기**는 예약입니다(수집이 멈춰 있으면 그렇게 알려 줍니다). 어제 것이 아직 남아 있으면 **며칠 전 브리핑인지 먼저 말합니다**. 카드는 만든 시각을 달고 있고, 테두리를 도는 빛은 이 카드가 세어진 것이 아니라 쓰인 것이라는 표시입니다. 그 아래 카드(누르면 해당 목록으로 이동) — 미처리·긴급·마감·초안, 그리고 **분석 실패는 있을 때만** 나타납니다. 미처리 카드는 **가장 오래된 건이 며칠 밀렸는지**까지 말합니다. **오늘 일정**(일정 화면과 같은 자료에서 오늘 날짜만 추려 보여주고, 누르면 그 메일이 열립니다), 종류·우선순위 분포, 일별 처리량, **할 일 판 요약**(대기·진행·완료), 마감 임박과 **지난 마감**(7/14/30일 전환). **고정한 메모**(메모 화면에서 압정을 누른 것만 올라오며, 여기서는 읽기만 합니다). 마감 목록은 **체크리스트**입니다 — 체크하면 그 메일이 처리 완료가 되고 위의 진행 막대가 함께 움직입니다. 막대와 추이는 값에 마우스를 올리면 날짜별 수치가 나옵니다. **다른 화면에서 한 일(삭제·처리 상태·초안·할 일)은 곧바로 이 숫자에 반영됩니다** |

| 일정 | 월·주·목록 달력. 일정을 누르면 그 메일이 열립니다. 마감(빨강 깃발)·시작(파랑 ▶)·확인 필요(회색 ?)를 **같은 크기의 아이콘과 서로 다른 색**으로 구분하고, 일정에 마우스를 올리면 **화면과 같은 모양의 말풍선**으로 날짜·종류·원문 근거와 지난 마감 여부를 보여줍니다. **시각이 있는 일정은 주 화면의 그 시간 칸에 들어갑니다** — `14:00 웨비나`는 종일 줄이 아니라 오후 2시 자리에 그려지고, 주 화면은 오전 8시 근처에서 열립니다. 날짜만 있는 마감은 그대로 종일 줄에 남습니다. 달력 아래 **직접 추가한 일정**에서 분석이 잡지 못한 일정을 손으로 올릴 수 있습니다 — 제목과 시작·마감 중 하나만 있으면 되고, 날짜는 `2026-09-22` 또는 `2026-09-22 15:00` 형식입니다. 읽을 수 없는 날짜는 저장하지 않고 이유를 알려 줍니다. 직접 추가한 일정은 **메일에 딸려 있지 않으므로 누를 메일이 없고**, 말풍선이 그렇게 말해 줍니다. 대시보드의 마감 체크리스트에도 함께 나오며 체크하면 그 일정만 완료가 됩니다. **Excel 일정 시트에는 나가지 않습니다** |

| 초안 | 답변이 필요한데 손대지 않은 초안을 한 건씩 검토. 입력을 멈추면 저장되고 목록에서 빠집니다. 검토하는 동안 새 초안이 도착하면 화면을 바꾸지 않고 **알림 줄**로만 알려 줍니다 — 쓰던 글이 지워지지 않게 하려는 것이고, **새로 고침**을 누르면 그때 목록을 다시 읽습니다 |
| 메모 | 메일도 일정도 할 일도 아닌 것을 적어두는 종이 벽입니다 — 전화번호, 양식이 있는 자리, 회의 중에 흘려 적은 한 줄. **새 메모**를 누르면 빈 쪽지가 생기고 커서가 바로 그 안에 들어가며, **입력을 멈추면 저장됩니다**(따로 저장 단추가 없습니다). 쪽지에 마우스를 올리면 **여섯 가지 색**과 **압정**, 지우기가 나옵니다 — 색을 바꿔도 쓰던 글은 그대로이고, 압정을 누르면 위쪽 **고정** 칸으로 올라가면서 **대시보드에도 나타납니다**. 위의 전체·고정·메일에 붙임으로 걸러 봅니다. **메모는 메일에 붙일 수 있습니다** — 메일 화면에서 메일을 열고 *이 메일에 메모 붙이기*를 누르면 그 메일의 메모가 되고, 다음에 그 메일을 열 때 원문 아래에 함께 나옵니다. 그 메일을 지워도 **메모는 지워지지 않고** 메모 화면에 남습니다. 다른 화면에서 메모가 바뀌면 화면을 바꾸지 않고 **알림 줄**로만 알려 줍니다 — 쓰던 글이 지워지지 않게 하려는 것으로, 초안 화면과 같습니다. 아무것도 적지 않은 빈 쪽지는 다음에 화면이 다시 그려질 때 조용히 사라집니다 |

**Codex 모델**은 설정 화면에서 라디오 버튼으로 고릅니다. 목록은 Codex CLI가 이 PC에
저장해 둔 것을 그대로 읽으므로, 지금 로그인한 계정으로 실제 쓸 수 있는 모델만 나옵니다.
**기본값**은 Codex가 정한 모델을 그대로 쓰며, 특별한 이유가 없으면 이쪽을 권합니다.
목록에 없는 이름을 쓰려면 **직접 입력**을 고르세요. Codex를 한 번도 실행한 적이 없는
PC에서는 목록이 비어 있고, `codex login` 이후 다시 열면 나타납니다.

주의할 점:

- **상담 화면은 메일 본문을 Codex로 보냅니다.** 분석과 같은 계정·같은 사용량 한도를
  쓰며, 분석이 돌고 있으면 그 뒤에 처리됩니다. 대화는 이 PC의 `mail.db`에만 저장되고
  화면에서 지울 수 있습니다.
- **창을 닫으면 도우미가 종료됩니다.** 수집을 계속 돌리려면 창을 열어 두세요(최소화해도
  됩니다). 브라우저로 연 탭은 닫아도 수집이 계속되며, 완전히 멈추려면 **실행**에서
  중지하세요.
- 창과 브라우저 화면을 같이 띄워도 수집기는 하나만 돕니다.
- **업데이트는 창 안에서 안내됩니다.** 새 버전이 있으면 대시보드 화면에 뜨고, 나중에를
  고르면 **실행** 화면의 업데이트에서 언제든 설치할 수 있습니다.

## 예시 파일 먼저 보기

시작 메뉴의 **메일 도우미 (진단)**를 열고 `MailAssistantTools.exe sample`을 실행하면 바탕화면에 `메일 업무관리 예시.xlsx`가 생성됩니다. 메일 수신과 Codex 분석 없이 샘플 메일 5건을 실제 반영 코드로 통과시켜, 도우미가 만드는 것과 같은 시트 구성·서식·달력을 보여줍니다. 지난 마감과 확인 필요 일정, 사용자가 직접 채우는 열의 예시까지 들어 있습니다. `MailAssistantTools.exe sample 경로.xlsx`로 위치를 지정할 수 있고 Excel이 없어도 동작합니다. 예시 파일은 도우미가 쓰는 파일과 별개이며 덮어써도 무방합니다.

## 대시보드

`대시보드` 시트는 첫 화면용 다크 테마 요약입니다. 데이터 시트와 일정 달력은 밝은 서식 그대로이며, `style.py`의 `DASH_*` 색상만 바꾸면 밝은 화면으로도 쓸 수 있습니다. 미처리 메일, 긴급·높음, 7일 내 마감, 검토 전 초안 네 개의 카드와 메일 종류·우선순위 분포, 최근 7일 수신량, 마감 임박 목록을 보여줍니다.

답변 초안 시트의 `답변 제목`을 누르면 기본 메일 앱에서 받는사람·제목·초안 본문이 채워진 답장 창이 열립니다(`mailto:`). 웹메일만 쓰고 기본 메일 앱이 없으면 동작하지 않으며, 초안이 길면 링크 길이 제한(1,800자)에 맞춰 잘립니다. 보내기 전에 내용을 반드시 확인하세요.

마감 임박 목록의 일정 이름을 누르면 메일 목록의 해당 메일 행으로 이동합니다. 일정·우선순위·답변 초안 시트의 `메일 ID` 셀도 같은 방식으로 메일 목록으로 연결됩니다. 워크북 안에서의 이동이며, 웹메일의 원본 메일을 여는 것은 아닙니다(POP3로는 웹 주소를 알 수 없습니다).

카드와 분포는 `COUNTIF`·`SUMPRODUCT` 수식이라 행이 늘면 엑셀이 알아서 다시 계산합니다. 도우미는 화면을 처음 한 번만 그리고, 이후에는 마감 임박 목록만 갱신합니다. 막대는 셀 안의 `REPT` 문자열로, 가장 큰 값을 기준으로 길이를 맞춥니다. 직접 고쳐도 다음 반영에서 되돌아갑니다.

`sample.py`의 달력 셀은 한 칸 안에서 줄마다 색이 다른 서식(rich text)을 씁니다. 줄바꿈만 들어 있는 텍스트 런은 `xml:space="preserve"` 없이 저장되어 Excel이 파일을 복구하려 하므로, 줄바꿈은 항상 다음 줄 텍스트에 붙여서 씁니다. 테스트가 생성된 파일의 모든 시트 XML을 검사합니다.

## 일정 달력과 서식

`일정 달력` 시트는 일정 시트의 시작·마감 날짜를 이번 달과 다음 달 월간 그리드로 다시 그립니다. 한 칸에 날짜와 일정 세 건까지 표시하고 그보다 많으면 `…외 N건`으로 줄입니다. `■ 마감`은 빨강, `▶ 시작`은 파랑, `◆ 확인 필요`는 회색이며 오늘 칸은 배경으로 강조합니다. 세 표시는 크기가 같은 한 벌이고 색이 서로 다른 세 가지라, 칸이 좁아도 어느 쪽인지 구분됩니다. 달력 범위보다 오래된 마감은 아래에 `지난 마감` 목록으로 따로 모읍니다. **이 시트는 매번 지우고 다시 그리므로 직접 적어 넣은 내용은 남지 않습니다.** 일정 내용을 고치려면 일정 시트를 수정하세요. 일정 시트에서 행을 지우면 달력에서도 사라집니다.

서식은 처음 한 번만 적용합니다. 표 스타일(줄무늬·필터), 헤더 강조, 첫 행 고정, 열 너비를 맞추고, 우선순위 열(긴급·높음·낮음)과 일정 시트의 마감 열(지난 마감, 3일 내 마감)에만 조건부 서식을 씁니다. 조건부 서식은 해당 열에서만 지우고 다시 만들기 때문에 다른 열에 직접 만든 규칙은 그대로 유지됩니다. 첫 행 고정을 적용할 때 시트가 잠깐 전환되며, 이후 반영에서는 서식 작업을 건너뜁니다. 달력이나 서식이 실패해도 메일 반영은 중단되지 않고 실행 상태 시트에 사유가 남습니다.

답변 초안의 ‘수신자’는 원본 발신자 표시입니다. Reply-To, 참조, 전체 답장 수신자는 실제 메일 앱에서 확인하세요. 초안을 검토·수정한 뒤 평소 쓰는 메일에서 직접 발송합니다.

기록 시각은 UTC ISO 형식이며 `+00:00`으로 표시됩니다(한국 시간은 9시간을 더함). 추출한 일정은 한국 시간 기준으로 해석하도록 지시합니다. AI가 작성한 날짜·우선순위는 검토가 필요합니다.

## 자동 시작 / 해제

설치 마법사의 **Windows 로그인 시 자동으로 시작** 항목을 체크하면 등록됩니다. 기본값은 해제이며, 수동 테스트를 마친 뒤 켜는 것을 권합니다.

나중에 켜려면 설치 프로그램을 다시 실행하고 해당 항목을 체크하세요. 끄려면 `Win+R` → `shell:startup`에서 **메일 도우미** 바로가기를 삭제하거나, 작업 관리자의 시작 프로그램 탭에서 사용 안 함으로 바꾸면 됩니다.

자동 시작으로 켜진 경우 설정이 저장되어 있으면 창이 열린 직후 스스로 **시작**을 누릅니다.

## Windows 인수 테스트

실제 메일/계정이 없는 개발 환경에서는 아래 항목을 검증할 수 없습니다. 친구 PC에서 이 순서대로 확인하세요.

**메일 계정 없이 엑셀 연결부터 확인하려면** 설치 폴더에서 다음을 실행하세요. 바탕화면에 별도의 `메일 업무관리 샘플.xlsx`를 만듭니다. 이를 엑셀에서 열어둔 채 같은 명령을 다시 실행하면 새 샘플 행이 추가됩니다. 실제 메일을 읽거나 Codex를 호출하지 않습니다.

```powershell
MailAssistantTools.exe demo
```

**같은 명령을 두 번 실행하세요.** 두 번째 실행이 기존 시트에 행을 덧붙이는 경로를 지나며,
자동 테스트가 덮지 못하는 부분입니다.

1. **첫 실행:** ‘첫 연결 완료’를 확인하고 바탕화면의 엑셀 파일과 5개 시트가 생성되는지 확인.
2. **새 메일:** ‘9월 20일까지 견적을 부탁드립니다’처럼 명확한 요청 메일 전송. 네 업무 시트에 결과가 생기는지 확인.
3. **열린 엑셀:** 엑셀을 열고 다른 시트/셀을 선택한 상태에서 두 번째 메일 전송. 선택 위치가 유지되며 새 행이 생기는지 확인.
4. **직접 편집:** 기존 처리 상태를 ‘완료’, 사용자 수정본을 임의 문장으로 변경. 재시작해도 유지되는지 확인.
5. **잠금/편집 중:** 셀 편집 또는 대화상자를 유지한 채 새 메일 처리. 대기를 확인하고 편집을 마친 뒤 한 번만 반영되는지 확인.
6. **닫힌 파일:** 엑셀을 닫고 새 메일 처리 후 다시 열어 저장 결과 확인.
7. **여러 Excel 인스턴스:** 다른 통합문서를 별도 인스턴스로 열어두고 대상 파일만 변경되는지 확인.
8. **재시작:** 도우미 종료 후 실행. 기존 메일 중복 없이 새 메일만 추가되는지 확인.
9. **실패 복구:** 인터넷을 끊었다 복구하거나 Codex 로그아웃 후 재로그인. 대기 메일이 재처리되는지 확인.
10. **자동 시작:** 등록 후 Windows 로그아웃/로그인. 중복 프로세스 없이 자동 처리되는지 확인.

웹 화면도 함께 확인합니다.

11. **구성 요소:** `MailAssistantTools.exe selftest` — `nicegui`, `mail_assistant.webui`, `nicegui ECharts 자산`, `pywebview (창)` 항목까지 정상인지 확인.
12. **열기:** `MailAssistantTools.exe web --browser`. 열 페이지 전부 열리는지, 일정 화면에 달력이 그려지는지 확인(비어 있으면 자산이 빠진 것).
13. **토큰:** 주소에서 `?t=...`를 지우고 열어 내용이 보이지 않는지 확인.
14. **한 수집기:** 웹의 **실행**에서 시작한 뒤 창을 띄워도 중복 실행되지 않는지 확인.
15. **쓰기:** 초안을 고치고 다른 메일로 이동 → 돌아와서 유지되는지, 할 일 카드를 **끌어서** 다른 열로 옮기면 메일 목록의 상태가 바뀌는지 확인. 끌고 가는 동안 놓을 열에 파란 테두리가 서는지, 제자리에 놓으면 아무 일도 일어나지 않는지도 함께 본다.
16. **마감 체크:** 대시보드의 마감 목록에서 한 건을 체크 → 취소선이 그어진 채 목록에 남고, 진행 막대와 **7일 내 마감** 카드가 같이 줄어드는지 확인. 다시 누르면 되돌아온다.
17. **상담:** 질문을 Enter로 보내고, 답이 오는 동안 입력칸이 잠기는지 확인. 답이 도착하면 대화가 자동으로 맨 아래까지 내려오는지도 본다.
18. **대시보드 카드:** 분석이 실패한 메일이 있으면 **분석 실패** 카드가 나타나고, 누르면 메일 목록이 실패 필터로 열리는지 확인. 실패가 0이면 카드가 아예 없어야 한다.
19. **탭 닫기:** 브라우저를 닫아도 수집이 계속되고, **실행**의 중지로 멈추는지 확인.
20. **목록 정렬·열기:** 메일 목록에서 **제목**을 눌러 ㄱ 순으로, 다시 눌러 역순으로 바뀌는지
    확인(누른 열에만 화살표가 선다). 행을 누르면 상세가 창 위에 열리고 `Esc`로 닫히는지,
    체크박스를 눌렀을 때는 상세가 열리지 **않는지** 함께 본다. 여러 건을 고른 뒤 한 건을
    열었다 닫아도 체크가 유지되어야 한다.
21. **가져오기·삭제:** **지금 가져오기**를 누르면(수집 중이 아니어도) 그 자리에서 연결해
    새 메일을 가져오고 결과가 실행 기록에 남는지 확인. 한 건을 골라 **삭제** → 확인 창이
    뜨고, 지운 뒤 **지금 가져오기**를 다시 눌러도 같은 메일이 돌아오지 않아야 한다.
28. **분석 중:** 분석이 도는 동안 메일 목록을 열어 둔 채로 둔다. 새로 고치지 않아도 그 메일의
    상태가 **분석 중**(주황)으로 바뀌었다가 분석이 끝나면 **미처리**로 바뀌어야 하고, 그러는
    동안 다른 행에 해 둔 체크는 풀리지 않아야 한다. 분석 중인 메일을 골라 **다시 분석**을
    누르면 '지금 분석 중이라…'가 뜨고 분석은 그대로 진행된다.
29. **대시보드 연계:** 대시보드와 메일 화면을 각각 브라우저 탭으로 열어 둔다. 메일에서 한 건을
    삭제하거나 처리 완료로 바꾸면 **대시보드 탭을 건드리지 않아도** 카드 숫자와 오늘 일정이
    1~2초 안에 따라 움직이는지 확인.
30. **오늘 일정:** 오늘 마감인 일정이 있으면 대시보드의 **오늘 일정**에 나타나고, 누르면 그
    메일이 열리는지 확인. 그 메일을 처리 완료로 바꾸면 목록에서 빠져야 한다.
31. **할 일 치우기:** 할 일 판에서 메일 카드의 휴지통을 누르면 카드만 사라지고 메일 목록에는
    그대로 있는지 확인. 그 메일을 열면 **할 일 판에 다시 올리기**가 보이고, 누르면 판에
    돌아와야 한다.
32. **오늘의 AI 브리핑:** 실행을 시작하고 한 주기를 기다린 뒤(오전 8시 이후여야 한다)
    대시보드 맨 위에 브리핑이 나타나는지 확인. 나타나기 전에는 *언제 만들어지는지*가 적혀
    있어야 하고, 만들어진 뒤에는 **만든 시각**이 제목 옆에 붙는다. **먼저 볼 메일** 칩을
    누르면 그 메일이 열린다. **다시 만들기**를 누르면 '예약했습니다/요청했습니다'가 뜨고,
    다음 수집 차례에 내용이 바뀐다. 날짜를 넘겨 다시 열면 **며칠 전 브리핑**이라는 띠가
    먼저 보여야 한다. 분석 대기가 쌓여 있는 동안에는 만들어지지 않는다.
33. **사이드바 숫자:** 왼쪽 **메일·할 일·초안**의 숫자가 대시보드의 같은 이름 카드와 일치하는지
    확인. 한 건을 처리 완료로 바꾸면 **사이드바를 건드리지 않아도** 몇 초 안에 줄고, 0이 되면
    숫자가 사라져야 한다. 창을 좁히면(1200px 미만) 사이드바가 저절로 아이콘만 남는다.
34. **사이드바 접기:** 위쪽 띠의 **≡ 단추**를 누르면 사이드바가 아이콘만 남기고 접히고,
    **숫자는 그대로 보여야** 한다. 아이콘에 마우스를 올리면 이름이 뜬다. 다른 화면으로
    옮기거나 창을 닫았다 열어도 접힌 채로 있어야 하고, 다시 누르면 펴진다.
35. **위쪽 띠:** 수집을 시작하면 오른쪽 표시가 **수집 중**으로 바뀌며 점이 깜박이고, 중지하면
    **수집 멈춤**이 되는지 확인. 메일 목록에서 검색어를 친 채로 이 변화가 일어나도 입력한
    글자가 지워지지 않아야 한다. 대시보드에서 카드를 눌러 들어간 뒤 **뒤로가기 화살표**로
    대시보드로 돌아오는지도 본다.
36. **일정 직접 추가:** 일정 화면 아래에서 제목과 마감(`2026-09-22`)을 넣고 **추가** →
    달력 그 날짜에 빨강 깃발로 나타나고 아래 목록에도 남는지 확인. 날짜 칸에 `다음 주 화요일`
    처럼 읽을 수 없는 값을 넣으면 저장되지 않고 형식을 알려 주어야 한다. 시작·마감을 모두
    비우면 거부한다.
37. **직접 추가한 일정의 연계:** 그 일정에 마우스를 올리면 말풍선이 **직접 추가한 일정입니다**
    라고 하고, 눌러도 메일 화면으로 넘어가지 않아야 한다. 대시보드의 **마감 임박** 목록에
    같은 일정이 링크 없이 나오고, 체크하면 그 줄만 완료로 바뀌며 **7일 내 마감** 카드가
    하나 줄어야 한다. 일정 화면에서 휴지통을 누르면 달력에서도 사라진다.

38. **메모 쓰기:** 메모 화면에서 **새 메모** → 빈 쪽지가 생기고 **커서가 이미 그 안에** 있어야
    한다. 두 줄쯤 치고 잠깐 멈춘 뒤 다른 화면에 갔다 돌아오면 그대로 남아 있는지 확인.
    쪽지에 마우스를 올려 **색을 바꿔도 쓰던 글이 그대로**여야 하고, **압정**을 누르면
    위 **고정** 칸으로 올라가면서 **글이 지워지지 않아야** 한다 — 여기서 글이 날아가면
    쪽지가 다시 그려질 때 저장이 늦은 것이다. 아무것도 적지 않고 새 메모를 한 번 더 누르면
    빈 쪽지가 늘어나지 않고 하나만 남는다.
39. **메일에 붙인 메모:** 메일을 열고 **이 메일에 메모 붙이기** → 원문 아래에 쪽지가 생기고,
    적은 뒤 메일을 닫았다 다시 열면 그대로 있는지 확인. 메모 화면에서 **메일에 붙임**으로
    거르면 그 메모가 나오고 메일 제목이 칩으로 붙어 있어야 한다. 그 **메일을 지워도 메모는
    남고**, 칩만 사라진다 — 지워지면 사용자가 쓴 글을 앱이 버린 것이다.
40. **고정한 메모:** 압정을 누른 메모가 **대시보드 오른쪽 아래**에 나타나는지 확인. 메모
    화면에서 압정을 풀면 대시보드에서도 몇 초 안에 사라진다.

창 자체는 CI가 띄워보지 못하므로 **아래 세 가지는 사람이 확인해야 합니다.**

41. **창이 뜨는가:** 바로가기를 눌러 창이 열리고 대시보드 화면이 그려지는지 확인. 빈 창이거나
    아무것도 안 뜨면 데이터 폴더의 `window.log`를 본다(WebView2 런타임 문제일 수 있다).
42. **폴백:** `MailAssistant.exe --window`로 예전 tkinter 창이 그대로 열리는지 확인.
    pywebview가 없는 PC에서 자동으로 이쪽으로 떨어지는 것이 이 줄이 지키는 동작이다.
43. **창 닫기 = 종료:** 창을 닫은 뒤 작업 관리자에 `MailAssistant.exe`가 남지 않는지,
    그리고 바로 다시 실행했을 때 "이미 실행 중입니다"가 뜨지 않는지 확인(뮤텍스가 풀렸다는 뜻).
44. **창 크기:** 처음 열었을 때 대시보드의 두 단이 가로 스크롤 없이 들어오는지 확인. 노트북
    화면에서도 제목 표시줄이 바탕화면 밖으로 나가지 않아야 한다.
45. **Codex 모델:** 설정에서 모델을 하나 고르고 저장 → 메일을 한 건 분석해 성공하는지
    확인. `config.json`의 `model` 값이 고른 슬러그와 같아야 하고, **직접 입력**으로 없는
    이름을 넣으면 분석이 실패하고 실행 기록에 남는다.
46. **업데이트 지금 확인:** 설정의 **지금 확인**이 **최신 버전입니다**를 보이고 마지막 확인
    시각이 갱신되는지 확인. 인터넷을 끊고 다시 누르면 '연결하지 못했습니다'가 나와야 한다 —
    끊긴 채로 '최신'이라고 하면 이 기능은 거짓말을 하는 것이다.

## 오류 해결

**먼저 최신 버전인지 확인하세요.** 도우미는 켤 때 새 버전을 확인하고 물어봅니다. 수동으로 올리려면 [Releases](https://github.com/gakmax/mail-assistant/releases/latest)에서 최신 Setup을 받아 그대로 실행하면 됩니다 — 기존 설정·메일 기록·엑셀 파일은 유지됩니다. 창 제목에 현재 버전이 표시됩니다.

`엑셀 반영 대기:`가 반복되면 도우미에 표시되는 `엑셀 반영 대기:` 이후의 전체 문구를 확인하세요. `%LOCALAPPDATA%\HiworksMailAssistant\status.json`의 `message`에도 같은 내용이 남습니다. 오류에 로컬 파일 경로가 포함될 수 있습니다. 계정 비밀번호나 메일 원문을 공유할 필요는 없습니다.

`메일 연결 실패`만 반복되고 원인을 알 수 없을 때는 시작 메뉴의 **메일 도우미 (진단)**을 열고 `MailAssistantTools.exe diagnose 메일주소`를 실행하세요. 자격 증명 저장 여부, DNS, TLS, 로그인, UIDL 지원을 순서대로 확인하고 실패한 단계의 서버 응답을 그대로 보여줍니다. 비밀번호는 화면에 출력하지 않습니다. 도우미 자체 메시지도 이제 실패 원인을 뒤에 덧붙여 표시합니다.

`엑셀 반영 대기: ... 열 구성이 바뀌었습니다`가 나오면 `MailAssistantTools.exe diagnose --excel`을 실행하세요. 설정에 지정된 파일을 읽기 전용으로 열어 시트별 1행을 기대값과 비교하고, 다른 셀의 현재 글자를 그대로 보여줍니다. 앞뒤 공백이나 셀 서식 차이는 도우미가 알아서 헤더를 다시 써서 넘어가고, 열 이름·순서가 실제로 바뀐 경우에만 반영을 멈춥니다.

1행이 `Column1`, `Column2`…로 바뀌어 있으면 표를 만들 때 Excel이 헤더 행을 인식하지 못해 자기 이름을 써넣은 경우입니다. 도우미가 다음 반영에서 1행을 원래 열 이름으로 되돌리고, 아래로 밀린 헤더 사본 행을 지웁니다. 수동으로 고칠 필요는 없으며 데이터 행은 그대로 유지됩니다.

엑셀에 기대한 행이 없을 때는 `MailAssistantTools.exe diagnose --result`로 저장된 분석 결과를 확인하세요. 종류·우선순위·일정 건수와 `reply_needed` 값을 보여줍니다. `reply_needed = False`면 모델이 답변 불필요로 판단한 것이며 답변 초안 시트에는 행을 만들지 않습니다. 값이 `True`인데 시트에 행이 없으면 엑셀 반영 문제입니다.

| 증상 | 확인할 내용 |
|---|---|
| 메일 연결 실패 | 서버 주소·포트, 해당 서비스의 POP3 사용 설정, 앱(메일 전용) 비밀번호, 허용 국가/IP, SSL 995 접근 |
| `ModuleNotFoundError: win32timezone` | 0.4.1 이하의 설치본 문제입니다(비밀번호 저장과 수집이 모두 막힙니다). 0.4.2 이상으로 업데이트하세요 |
| Codex 로그인 안내 | 도우미의 Codex 로그인 버튼 또는 `codex login`, `codex login status` |
| 분석 대기 | Plus 사용량 한도, 인터넷, Codex CLI 업데이트, 과도하게 긴 본문 |
| 엑셀 반영 대기 | Excel 설치/인증, 입력 중인 셀·대화상자, 읽기 전용, 파일 위치, 시트 열 이름 |
| 엑셀이 열려 있는데 인식 안 됨 | 다른 창으로 잠시 전환해 Excel이 자동화 대상으로 등록되게 한 뒤 재시도 |
| 바로가기 실행이 안 됨 | 시작 메뉴 → **메일 도우미 (진단)** → `MailAssistantTools.exe gui`로 오류 메시지 확인 |
| 창이 빈 화면이거나 열리지 않음 | WebView2 런타임이 없는 PC일 수 있습니다. `MailAssistant.exe --window`로 예전 창을 쓰거나, Microsoft의 **Edge WebView2 Runtime**을 설치하세요. 자세한 사유는 데이터 폴더의 `window.log`에 남습니다 |
| 창이 잠깐 떴다 사라짐 | `%LOCALAPPDATA%\HiworksMailAssistant\startup-error.log` 확인 |
| 구성 요소 이상이 의심될 때 | `MailAssistantTools.exe selftest` |
| 원인을 단계별로 보고 싶을 때 | **설정** 화면의 **점검** |
| 웹 화면의 일정이 비어 있음 | 설치가 손상되어 달력 자산이 빠진 경우. `selftest`로 확인 후 재설치 |
| 대시보드·통계의 그래프가 비어 있음 | 차트 자산이 빠진 경우. `selftest`의 `nicegui ECharts 자산` 항목으로 확인 후 재설치 |
| 오늘의 AI 브리핑이 안 만들어짐 | 실행이 멈춰 있거나, 오전 8시 전이거나, 분석 대기가 남아 있는 경우입니다. 카드가 셋 중 어느 쪽인지 말해 줍니다. Codex 호출이 실패하면 30분 뒤 다시 시도하며 **실행** 화면에 남습니다 |
| 글꼴이 평소와 달라 보임 | 화면 글꼴(Pretendard)이 함께 설치되지 않은 경우. `selftest`의 `mail_assistant.webui` 항목으로 확인. 글꼴이 없어도 기능은 그대로다 |

분석 실패는 5분부터 최대 1시간 간격으로 재시도하며 다른 메일의 분석도 잠시 대기합니다. 엑셀 반영 실패는 분석을 다시 호출하지 않고 저장된 결과를 재사용합니다. 메일 수집은 한 주기 최대 25건, 분석은 최대 5건, 엑셀 반영은 최대 50건씩 처리합니다.

## 오류 자동 보고

오류가 나면 개발자의 Discord로 내용이 자동 전송됩니다. 보내는 것은 **오류 종류와 호출 위치(스택 트레이스), 발생 시각, PC 이름, 프로그램 버전**뿐입니다. 메일 본문·제목·첨부와 Codex 응답은 보내지 않으며, 메일 전용 비밀번호는 `***`로, 메일 주소는 `ho***@도메인` 형태로 가려서 전송합니다.

같은 오류는 30분에 한 번, 전체는 시간당 20건까지만 보냅니다. 전송에 실패해도 도우미 동작에는 영향이 없습니다.

끄려면 `%LOCALAPPDATA%\HiworksMailAssistant\config.json`에 다음 항목을 추가하고 도우미를 다시 시작하세요.

```json
"webhook": ""
```

다른 주소로 보내려면 같은 항목에 새 Webhook URL을 적으면 됩니다. 환경 변수 `MAIL_ASSISTANT_WEBHOOK`을 지정하면 그 값이 우선합니다.

웹훅 주소는 소스에 들어 있지 않습니다. 릴리스 빌드에만 주입되므로, 저장소를 직접 빌드하면 기본값이 비어 있어 아무것도 보내지 않습니다.

## 자동 업데이트

도우미를 켤 때 새 버전이 있는지 확인하고, 있으면 변경 내용과 함께 물어봅니다. **지금 업데이트**를 누르면 설치 파일을 내려받아 SHA-256으로 확인한 뒤 조용히 설치하고 도우미를 다시 엽니다. 설정, 메일 기록(`mail.db`), 엑셀 파일, 저장된 비밀번호는 그대로 유지됩니다. 내려받는 동안 진행률이 보이며 언제든 취소할 수 있습니다.

도우미가 실행 중일 때 업데이트하면 **현재 메일·분석·엑셀 작업을 마친 뒤** 설치합니다. Codex 분석 한 건의 제한 시간이 4분이라 몇 분 걸릴 수 있습니다.

**설정**과 **실행** 화면의 업데이트에서 **지금 확인**을 누르면 주기를 기다리지 않고
바로 확인합니다. 결과는 세 가지로 구분해 알려 줍니다 — 새 버전이 있을 때, **최신
버전입니다**, 그리고 GitHub에 닿지 못했을 때. 마지막으로 확인한 시각도 같이 보이므로,
조용한 화면이 '최신'인지 '못 물어봤다'인지 헷갈리지 않습니다.

확인은 6시간에 한 번, 공개 GitHub Releases에서만 합니다. 인터넷이 끊겨 있거나 GitHub에 접속할 수 없으면 아무것도 표시하지 않고 평소대로 실행합니다. **이 버전 건너뛰기**를 누르면 다음 버전이 나올 때까지 다시 묻지 않습니다. Windows 로그인 자동 시작으로 켜진 경우에는 60초 뒤 창이 스스로 닫히고, 창 오른쪽 위의 **⬆ 업데이트** 버튼으로 언제든 다시 설치할 수 있습니다.

끄려면 `%LOCALAPPDATA%\HiworksMailAssistant\config.json`에 다음 항목을 추가하고 도우미를 다시 시작하세요.

```json
"update": false
```

설치 파일에는 코드 서명이 없습니다. SHA-256 확인은 내려받는 도중 파일이 깨지거나 일부만 받아진 경우를 걸러 내며, GitHub 계정 자체가 탈취된 경우까지 막지는 못합니다. 검증 파일이 없거나 해시가 다르면 설치하지 않고 받은 파일을 지웁니다.

## 제거

**설정 → 앱 → 설치된 앱 → 메일 도우미 → 제거**, 또는 시작 메뉴의 **메일 도우미 제거**를 실행합니다. 관리자 권한은 필요 없습니다.

제거해도 **지워지지 않는 것**은 다음과 같습니다. 실수로 업무 기록을 잃지 않도록 일부러 남깁니다.

- `%LOCALAPPDATA%\HiworksMailAssistant` 폴더 (`config.json`, `mail.db`, `status.json`)
- Windows 자격 증명 관리자의 `HiworksMailAssistant/<메일주소>` 항목
- 엑셀 워크북 (기본값은 바탕화면의 `메일 업무관리.xlsx`)

완전히 지우려면 위 세 가지를 직접 삭제하세요. 반대로 재설치하면 기존 설정과 메일 기록을 그대로 이어받습니다.

## 데이터와 백업

`%LOCALAPPDATA%\HiworksMailAssistant`에 다음 파일이 있습니다.

- `config.json`: 서버, 계정, 엑셀 위치 등 설정(비밀번호 제외)
- `mail.db`: 원문 메일, 분석 결과, 처리 이력. 실행 기록(`log`), 직접 적은 할 일(`todo`),
  상담 대화(`chat`), 메모(`note`)도 같은 파일에 있습니다. SQLite 파일이며 암호화되어 있지 않습니다.
- `status.json`: 최근 실행 상태. 메일 본문이나 비밀번호를 기록하지 않습니다.

백업은 도우미를 중지한 뒤 데이터 폴더와 엑셀을 함께 복사하세요. DB를 삭제하면 기존 메일의 처리 이력이 사라지고 다음 연결에서 새 기준점을 잡습니다. 비밀번호는 Windows 자격 증명 관리자에서 `HiworksMailAssistant/메일주소` 항목으로 관리합니다.

업데이트 중에는 `update/<버전>/` 하위 폴더에 설치 파일이 잠시 생겼다가 다음 실행 때 정리됩니다. **프로그램을 제거해도 이 폴더는 지워지지 않습니다.**

## 첫 버전 범위

- 본문(텍스트/HTML)과 첨부 **이름**을 분석. 첨부 내용/OCR은 미지원.
- 본문 60,000자 초과는 자동 분석하지 않고 대기 처리. 원문은 DB에 보관.
- Excel 셀의 긴 내용은 32,700자까지 표시하며 전체 분석 결과는 DB에 보관.
- 답장에 인용된 본문은 제공하지만 별도 메일 간 스레드 검색은 미지원.
- 일정은 엑셀과 앱 안의 달력에만 기록. **구글·아웃룩 캘린더 연동과 `.ics` 내보내기, 메일 자동 발송은 미지원** — 메일 내용은 Codex 외부로 나가지 않습니다.
- 직접 추가한 일정은 앱 안에서만 보입니다(달력·대시보드). Excel 일정 시트는 분석 결과만 담습니다.
- 한 PC, 한 실행 계정, 한 대상 통합문서 구성. 개인 PC 로그인 세션용이며 Windows 서비스/공유 서버용이 아님.
- COM 연동은 실제 Windows/Excel에서 위 인수 테스트가 필요합니다. Linux 개발 테스트만으로 화면 갱신을 보증할 수 없습니다.

## 개발과 릴리스

테스트는 어느 플랫폼에서나 돕니다. Windows API와 Excel COM은 전부 가짜로 주입하므로 Linux에서도 전부 통과합니다.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Windows에서 exe와 설치 프로그램을 직접 만들려면 [Inno Setup 6](https://jrsoftware.org/isdl.php)을 설치한 뒤:

```powershell
.\packaging\build.ps1
```

`dist\installer\`에 `MailAssistant-Setup-x.y.z.exe`, `.sha256`, `latest.json`이 생성됩니다.

**릴리스 절차**는 세 단계입니다.

1. `mail_assistant/__init__.py`의 `__version__`을 올립니다. **버전이 적힌 곳은 여기 하나뿐이며** 설치 프로그램, exe 버전 리소스, 업데이트 비교값이 전부 여기서 파생됩니다.
2. 커밋하고 `git tag -a v0.2.0 -m "메일 도우미 0.2.0"` → `git push --follow-tags`.
   **태그는 반드시 `-a`로 만듭니다** — `--follow-tags`는 가벼운 태그를 밀지 않으므로
   `git tag v0.2.0`은 아무것도 올리지 못하고 릴리스도 만들어지지 않습니다.
3. GitHub Actions가 Windows에서 테스트 → PyInstaller → 고정 빌드 점검(`selftest`) → Inno Setup → 릴리스 게시까지 처리합니다. 태그와 `__version__`이 다르면 빌드를 실패시킵니다.

Discord 웹훅은 소스에 없습니다. CI가 저장소 시크릿 `DISCORD_WEBHOOK`으로 `mail_assistant/_secrets.py`를 만들어 넣으며, 직접 빌드하면 기본값이 비어 있어 아무것도 보내지 않습니다. 공개 릴리스 파일에서 문자열을 추출하는 것은 막지 못하므로, 남용되면 Discord에서 웹훅을 재발급하고 시크릿만 교체하면 됩니다.

`latest.json`은 버전이 붙지 않은 고정 이름입니다. 업데이터가 `releases/latest/download/latest.json` 리다이렉트로 읽으므로 **이름을 바꾸면 구버전이 업데이트를 찾지 못합니다.**
